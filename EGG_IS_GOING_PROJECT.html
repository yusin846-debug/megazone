egg is going — 제작회의 워크스페이스 (바이브 코딩 팀 프로젝트)

팀 확정 주제 · 제안서: Egg_Is_Going_Proposal.pdf (12장) · 정리: 2026-10-20 가상 제작사 대상 교육 프로젝트. 실제 기업과 무관.

1. 제안서 요약

장 핵심
01 “회의가 끝나면, 제작이 시작되도록.” 제작회의 워크스페이스 제안
02 페르소나: 막내 작가. 하루 12시간 중 회의 관련 9시간, 그중 문서 작업 약 4.5시간 (방송작가 인터뷰를 가상 제작사에 적용한 가설)
03 작가팀·PD팀이 함께 한 회의 → 막내 작가 혼자 문서 작업 → 상위 검토·결재 → 내용·서식 수정 반복. 재확인과 인수인계 부담
04 줄여야 할 일 4가지: ① 맥락 다시 찾기(원문 근거·변경 이력) ② 양식 다시 맞추기(프로그램별 승인 템플릿) ③ 전체 다시 검토(누락 검사·수정 비교) ④ 다음 일 다시 묻기(담당·기한·보류)
05 “해석은 에이전트가, 확인은 사람이.” 전사·화자 → 제작 맥락·결정 → 문서 구성·출력 → 원문 검증. 에이전트와 규칙 기반 도구 역할 분리. 오케스트레이션 스튜디오(실행 조건, 사람 확인, 부분 재실행, 버전·로그). 현업은 하나의 웹에서 검토·상신
06 회의 작업실 화면: 원문(타임스탬프·음성) ↔︎ 정리된 결정(변경 내용, 근거 시각, 담당·기한)
07 바뀐 부분만 다시 실행. 단계별 상태, 사람 확인 필요 표시. 템플릿 변경 시 문서 출력·서식 검사만 재실행. 승인 이력 보존
08 문서 작업 4.5시간 → 2시간 (약 56% 감소 목표, 검증 전)
09 팀 순효과 = 역할별 확보 시간 − 추가 검토·운영 시간
10 첫 PoC: 프로그램 1개·템플릿 1종, 실제 작성자·검토자 참여, 작업 시간·누락·반려 횟수 측정. 통과 기준: 평가 표본의 중대한 결정 누락 0건
11 회의의 맥락은 남기고, 반복 작업은 줄이고
12 브랜드 해석과 디자인 원칙

2. 바이브 코딩 MVP 범위 (개발자 1명 기준)

화면 3개 (+1)

# 화면 제안서 장 핵심
1 업로드·실행 상태 07 녹취록(또는 음성) 업로드 → 단계별 진행 상태 → 단계별 [다시 실행]
2 회의 작업실 06 왼쪽 원문(타임스탬프·화자), 오른쪽 정리된 결정. 결정 클릭 → 근거 구간 하이라이트
3 문서 검토·상신 05·10 템플릿에 채워진 회의록 미리보기, 누락·서식 검사 결과, [승인]·[반려+사유], 이력
(4) 템플릿 관리 04·07 템플릿 1종의 칸 정의. 시간이 남을 때만

처리 흐름

① 입력        녹취록 텍스트 (타임스탬프·화자 포함)  ※ 음성 → 전사는 여유 있을 때
     ↓
② 해석 (LLM)  결정 / 변경 이력 / 보류 / 담당·기한 → 구조화 JSON
     ↓
③ 검증 (규칙)  필수 칸 존재, 근거 타임스탬프가 원문에 실제 있는지, 담당자가 참석자 명단에 있는지
     ↓
④ 출력 (규칙)  템플릿 머지 → 회의록 문서
     ↓
⑤ 사람 확인   검토·승인·반려 (이력 저장)
  • 에이전트(LLM)는 ②만, 나머지는 규칙 기반 코드 → 제안서 05장 “역할 분리”와 일치
  • 단계별 결과를 DB에 저장 → 템플릿만 바뀌면 ④·⑤만 재실행 (제안서 07장)

해석 결과 형식 (예시)

{
  "decisions": [
    {
      "topic": "오프닝 장소",
      "final": "스튜디오",
      "history": [
        {"value": "야외", "at": "00:12", "speaker": "메인 PD"},
        {"value": "스튜디오", "at": "00:48", "speaker": "메인 작가", "reason": "우천 예보"}
      ],
      "evidence": ["00:48", "00:51"],
      "owner": null,
      "due": null,
      "status": "확정"
    }
  ],
  "pending": [{"topic": "게스트 섭외", "reason": "출연료 확인 필요", "evidence": ["03:20"]}],
  "action_items": [{"task": "스튜디오 대관 확인", "owner": "서브 PD", "due": "10/24", "evidence": ["05:02"]}]
}
  • owner·due가 원문에 없으면 “미정”으로 남긴다 (지어내지 않기)

기술 구성 (강사 지정 도구 우선)

Next.js + Supabase + LLM API(서버에서만 키 사용) + Vercel. 음성 전사가 필요하면 음성 인식 API 추가.

3. 평가 데이터: 비개발자 팀원의 핵심 역할

가상 제작회의 녹취록 5개를 직접 만든다. (대본 작성 → 팀원끼리 연기 → 녹음·전사)

회의 꼭 넣을 함정
1. 기본 기획 회의 결정 3개, 할 일 3개 (기준선)
2. 번복이 많은 회의 결정이 두 번 바뀜 (“야외 → 스튜디오 → 다시 야외 검토”)
3. 보류가 많은 회의 “다음 주에 다시 보자”, 담당 미정
4. 잡담 섞인 회의 농담·사담 속 진짜 결정 하나
5. 동시 발화·끊김 말이 겹치고 화자가 헷갈리는 구간

각 회의마다 정답지(중대한 결정, 할 일, 보류, 근거 시각)를 미리 작성 → 도구 결과와 비교.

측정 지표 (제안서 10장 기준)

지표 목표
중대한 결정 누락 0건 (통과 기준)
근거 시각 정확도 정답지 구간과 겹치는 비율
지어낸 담당·기한 0건
서식 오류 규칙 검사 후 0건
작성 시간 사람이 처음부터 vs 도구 + 검토 (팀원이 직접 측정)
반려 횟수 검토자 역할 팀원이 반려한 횟수

4. 팀 역할 (안)

사람 역할 맡는 일
나 기술 리드 처리 흐름(②~⑤), LLM 해석 프롬프트, 규칙 검사, 부분 재실행, 배포 뼈대
팀원 A 평가·시나리오 가상 회의 대본 5개, 녹음, 정답지, 측정·결과표
팀원 B 템플릿·화면·발표 프로그램 회의록 템플릿 설계, 작업실·검토 화면(AI 코딩 도구로), 발표 자료

5. 데모 시나리오 (4분)

  1. (02장) 막내 작가의 하루 → “문서 작업 4.5시간”
  2. 번복이 많은 회의(2번) 녹취록 업로드 → 단계별 진행 표시
  3. 회의 작업실: “오프닝: 스튜디오 (야외에서 변경, 근거 00:48)” → 클릭하면 원문 구간 강조
  4. 담당·기한 “미정” 표시 → 검토 화면에서 사람이 채움
  5. 템플릿 한 칸 수정 → 문서 출력·서식 검사만 재실행 (07장)
  6. 검토자 [반려+사유] → 수정 → [승인] → 이력 남음
  7. 결과표: 회의 5개 기준 중대한 결정 누락 ○건, 작성 시간 ○분 → ○분

6. 확인·결정할 것

7. 내 다른 기획과의 연결

egg is going 연결
회의 → 결정·변경 이력 → 템플릿 → 사람 확인 MinuteMerge의 방송 제작 버전 (같은 엔진)

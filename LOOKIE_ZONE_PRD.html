Lookie Zone — 교육생·신입사원 온보딩 포털 기획서 (PRD 초안)

바이브 코딩 팀 프로젝트 · 팀원 3명 (개발 경험자 1명) · 작성: 2026-10-16

1. 한 줄 요약

“처음 온 사람이 묻고, 찾고, 신청하는 모든 것을 한곳에서. 담당자는 같은 질문에 두 번 답하지 않는다.”

교육생과 신입사원이 알아야 할 정보(편의시설, 셔틀, 규정)를 모아 두고, 휴가·자격증·문의 신청은 슬랙으로 담당자에게 바로 전달하며, 궁금한 건 AI 에이전트에게 물어 바로 답을 얻는 온보딩 포털이다.

2. 왜 필요한가

교육생·신입사원의 불편

  • 셔틀 시간, 식당 위치, 출결 규정 같은 정보가 공지·메신저·파일에 흩어져 있다
  • 사소한 걸 물어보기 눈치 보인다
  • 신청서를 어디에 어떻게 내야 하는지, 처리됐는지 모른다

교육·연수 담당자의 고충 (평가자인 운영진·강사가 겪는 문제)

  • 매 기수마다 같은 질문을 받는다 (일정, 장소, 출결, 훈련장려금, 휴가)
  • 신청이 메일·메신저·종이로 들어와서 누락되고 처리 상태를 따로 챙겨야 한다
  • 어떤 정보가 부족해서 질문이 몰리는지 데이터가 없다

3. 사용자

사용자 하고 싶은 것
교육생·신입사원 정보를 빨리 찾고, 눈치 안 보고 묻고, 신청 결과를 확인하고 싶다
운영진(담당자) 반복 질문을 줄이고, 신청을 한곳에서 처리하고, 공지를 쉽게 올리고 싶다
강사 (선택) 교육생이 자주 묻는 학습 관련 질문을 알고 싶다

4. 화면 구성

# 화면 사용자 핵심 기능 MVP 우선순위
1 물어보기 (에이전트) 교육생 규정·시설·일정을 자연어로 질문 → 근거 문서와 함께 답변. 못 답하면 담당자 문의로 넘김 ★★★
2 신청 센터 교육생 휴가·자격증 지원·문의 신청서 → 슬랙으로 담당자에게 알림. 내 신청 상태 확인 ★★★
3 운영자 콘솔 운영진 신청 승인·반려, 공지·게시글 관리, 에이전트가 못 답한 질문 목록 ★★★
4 정보 게시판 교육생 편의시설, 셔틀 시간표, 교육장 안내, 규정 모음 ★★
5 홈 교육생 오늘의 공지, 오늘 셔틀, 내 신청 현황을 한눈에 ★

화면이 5개라 3명이 하기엔 크다. 1·2·3을 먼저 완성하고, 4·5는 시간이 남으면 붙인다. 발표에서 감동을 주는 건 1(에이전트)과 3(운영자 콘솔)이다.

5. 기능 상세

5-1. 물어보기 (에이전트)

MVP 방식 (1개월 차 수준) - 규정·시설·셔틀 문서를 마크다운으로 정리해 두고, 질문할 때 문서를 AI에게 함께 넘겨 답하게 한다 - 답변 끝에 근거 문서 이름을 표시한다 (“출처: 출결 규정 3조”) - 문서에 없는 내용이면 지어내지 말고 “담당자에게 문의할까요?”로 넘긴다 → 문의 신청서가 미리 채워진 채 열린다 - 못 답한 질문은 DB에 쌓여 운영자 콘솔에 표시된다

에이전트다운 기능 (가능하면 추가) - “내 휴가 신청 어떻게 됐어?” → DB에서 내 신청 상태를 조회해 답한다 (도구 호출) - “다음 주 금요일 휴가 신청해 줘” → 신청서 초안을 채워서 보여주고, 사용자가 확인 버튼을 눌러야 제출된다

나중에 고도화 (과정 Step 6 이후) - 문서가 많아지면 벡터 검색(RAG)으로 바꾼다 → “처음엔 단순하게, 배운 만큼 고도화”라는 발표 이야기가 된다

5-2. 신청 센터 + 슬랙 연동

신청 종류 입력 항목 처리자
휴가 날짜, 사유, 증빙 첨부 여부 운영진
자격증 지원 자격증명, 응시일, 바우처 필요 여부 운영진
문의 분류(행정·시설·학습), 내용 분류별 담당자

슬랙 연동 단계 | 단계 | 방식 | 난이도 | |—|—|—| | MVP | 신청 저장 → 담당자 슬랙 채널에 알림 메시지 (Incoming Webhook) | 쉬움 | | 확장 1 | 슬랙 메시지의 [승인] [반려] 버튼으로 바로 처리 → 포털 상태 자동 변경 (Slack App + 버튼 응답 API) | 중간 | | 확장 2 | 처리 결과를 신청자에게 슬랙 DM으로 알림 | 중간 | | 확장 3 | 슬랙에서 봇에게 바로 질문 (물어보기 에이전트를 슬랙에서도) | 중간~어려움 |

5-3. 운영자 콘솔

  • 신청 목록 (대기·승인·반려 필터), 승인·반려 버튼
  • 공지·게시글 작성 (정보 게시판에 바로 반영)
  • 미답변 질문 TOP 10 → [FAQ로 추가] 버튼 → 규정 문서에 반영되면 다음부터 에이전트가 답한다
  • 간단한 통계: 이번 주 질문 수, 에이전트가 답한 비율, 신청 처리 평균 시간

“미답변 질문 → FAQ 추가 → 에이전트가 학습” 순환이 이 서비스의 핵심 메시지다. 운영진이 가장 공감할 장면.

7. 데이터 (모두 가짜 데이터)

데이터 예시
규정 문서 5~8개 출결 규정, 휴가 규정, 훈련장려금 안내, 자격증 지원 규정, 시설 이용 안내, 셔틀 시간표, 보안 수칙
게시글 편의시설(식당·카페·편의점·휴게실), 셔틀 노선과 시간, 교육장 층별 안내
테스트 질문 30개 “지각 몇 번이면 결석이야?”, “셔틀 막차 몇 시?”, “자격증 바우처 언제 신청해?”

실제 회사 내부 규정이나 동기들의 개인정보는 쓰지 않는다. 예시 회사 기준으로 가짜 규정을 만든다. 공개된 정보(캠퍼스 주소 등)만 참고한다.

8. 데모 시나리오 (3~4분)

  1. (문제) “교육 첫 주, 운영진은 같은 질문을 몇 번이나 받을까요?” (운영진 인터뷰 숫자 인용)
  2. (물어보기) “지각 3번이면 어떻게 돼?” → 근거 규정과 함께 답변
  3. (못 답하는 질문) “주차 등록은 어떻게 해?” → “담당자에게 문의할까요?” → 문의서가 채워진 채 열림 → 제출
  4. (슬랙) 운영진 슬랙 채널에 알림이 뜬다. (확장했다면) 슬랙에서 [승인] 클릭 → 포털 상태가 바뀜
  5. (운영자 콘솔) 미답변 질문 목록에서 “주차 등록” → [FAQ로 추가]
  6. (다시 물어보기) 같은 질문 → 이번엔 바로 답한다
  7. (마무리) “같은 질문에 두 번 답하지 않는 온보딩.”

9. 팀 역할

사람 역할 맡는 일
나 기술 리드 저장소·DB·로그인·배포 뼈대, 물어보기 에이전트 로직, 슬랙 연동, 코드 검토
팀원 A PM·운영 운영진 인터뷰, PRD 다듬기, 신청 센터 + 운영자 콘솔 화면 (AI 코딩 도구로 직접), 발표
팀원 B 콘텐츠·UX 규정 문서와 게시글 가짜 데이터 작성, 정보 게시판·홈 화면, 테스트 질문 30개로 에이전트 품질 점검

팀원도 화면 하나씩은 AI 코딩 도구로 직접 만든다. 나는 뼈대를 먼저 깔고 검토한다. 팀원 B의 규정 문서 품질이 에이전트 답변 품질을 결정한다. 가장 중요한 역할 중 하나다.

10. 일정 예시 (2주 기준, 기간에 맞게 조정)

기간 할 일
1~2일 운영진·강사 인터뷰 (15분씩), PRD 확정, 화면 스케치
3~4일 뼈대: Next.js + Supabase + 로그인 + Vercel 배포 (나) / 가짜 규정 문서 (B)
5~7일 물어보기 에이전트 (나) / 신청 센터 (A) / 정보 게시판 (B)
8~9일 슬랙 알림, 운영자 콘솔, 미답변 질문 순환
10~11일 테스트 질문 30개로 품질 점검, 버그 수정, (여유 있으면) 슬랙 승인 버튼
12~14일 데모 데이터 정리, 리허설, 발표

11. 성공 기준 (발표에서 보여줄 숫자)

지표 측정 방법
에이전트 정답률 테스트 질문 30개 중 근거와 함께 맞게 답한 비율
모르는 질문을 지어내지 않은 비율 문서에 없는 질문 10개 중 “담당자 문의”로 넘긴 비율
신청 처리 단계 기존(메일·메신저) 대비 클릭 수와 단계
운영진 예상 절감 시간 인터뷰에서 들은 “반복 질문에 쓰는 시간” × 에이전트 답변 비율

12. 주의할 점

  • 범위: 화면 5개 + 슬랙 + 에이전트는 크다. 1·2·3 화면과 슬랙 알림(Webhook)까지가 MVP. 나머지는 여유분.
  • 틀: “우리 과정의 불만”이 아니라 “기업 신입사원·교육생 온보딩” 일반으로 발표한다.
  • 개인정보: 실제 동기 정보, 실제 내부 규정은 쓰지 않는다.
  • AI의 한계 표시: 규정 답변에는 근거를 꼭 붙이고, “최종 판단은 담당자에게”라는 안내를 둔다.
  • 슬랙 권한: 슬랙 앱을 만들려면 워크스페이스 관리자 권한이 필요할 수 있다. 팀 전용 무료 워크스페이스를 하나 만들어 쓰는 게 편하다.

13. 최종 포트폴리오(AIR Deal Desk)와의 연결

Lookie Zone에서 연습하는 것 AIR Deal Desk에서 다시 쓰는 곳

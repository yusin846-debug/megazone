# 챗봇 기획과 구현 대조

v0.2 | 2026-10-22 | 검토용 초안 · 챗봇 추가안 (기준: IMPLEMENTATION_AUDIT.html 형식)

> 작업 순서 기록: 이 기능은 **코드를 먼저 만들고 나서** 기준 문서 01~05를 확인해 추가안을 작성했다. 원래 순서(AsIs → ToBe → PRD → ERD → 연동 → 화면 → 구현)와 반대이므로, 문서 작성 중 발견한 차이를 아래에 모두 적고 일부는 코드에 반영했다.

## 요구사항별 대조

| 요구사항 | 기획 | 구현 | 상태 |
|---|---|---|---|
| FR-11 범위 | 선택한 프로그램의 회의 원문 전체 | `loadCorpus(programId)` — 프로그램 조건으로만 조회, 전사 전 녹취록 포함 | ✅ |
| FR-11 격리 | 다른 프로그램 검색 불가 | `activeProgram()`이 멤버십 있는 프로그램만 허용 | ✅ (AT-06~08) |
| FR-12 표기 오류 | 받아쓰기 오류 고려 | 모음 한 개 차이 인정 + 자모 편집 거리. 동의어의 오타까지는 넓히지 않음 | ✅ |
| FR-12 비슷한 뜻 | 뜻이 비슷한 표현 | 제작 용어 사전 32묶음, Claude 모드에서 AI 확장 추가 | ✅ (AI 확장은 사람 검토 후 적용) |
| FR-13 표시 | 회의 이름·날짜·시간 | 회의 이름·날짜·회의 시작 시각·녹음 위치·화자·팀 | ✅ 발언별 실제 시각은 시각 버튼에 마우스를 올리면 툴팁으로 표시 (시안 B 적용 때 빠졌다가 다시 넣음). 휴대폰은 미표시 (결정 사항) |
| FR-13 이동 | 해당 부분으로 이동 | 작업실 `#seg_xx` 앵커 | ✅ (전사 전 회의는 작업실까지만) |
| FR-13 듣기 | 누르면 해당 부분 듣기 | 녹음 파일 있으면 구간 재생 / **없으면 브라우저 음성 읽기** | ⚠️ 대체 구현 |
| FR-08 권한 | 백엔드 검증 | 비로그인 401, 운영자 403 | ✅ (AT-09~10) |
| FR-14a 조회 기록 | 질문 1건당 기록, 원문 없음 | `audit()`로 AuditEvent 1행 (`chatbot.search` / `chatbot.search_denied`) | ✅ |
| FR-14b 사용량 기록 | 토큰·모델·응답 시간 | 미구현 | ⏸ Claude 모드 도입 시 |
| 원문 최소 로그 | 원문을 로그에 남기지 않음 | 오류 로그에는 오류 메시지만 남김 | ✅ |

## 기획과 다른 점

| 항목 | 차이 | 이유 | 후속 |
|---|---|---|---|
| 듣기 | 실제 녹음 대신 음성 읽기 | 현재 앱은 텍스트 녹취록만 저장 (`Recording.kind = text`) | 녹음 저장 방식 확정 후 자동 전환 (코드 준비됨) |
| 결론 발언 | mock 모드는 질문 단어가 없는 결론 발언을 못 찾을 수 있음 (예: "바닷가 오후 네 시로 확정") | 규칙 검색은 단어 일치 기반 | Claude 모드는 관련 회의 원문 전체를 읽고 결론 발언을 인용하도록 구현. 결과 발언 아래 "이어서" 다음 발언도 표시 |
| Run 미생성 | 챗봇 호출은 Run·StepRun을 만들지 않음 | 여러 회의를 가로지르는 짧은 조회 | 05_AIR_연계 참고 |
| 오류 안내 | 처음에는 영어 기술 오류가 화면에 그대로 보였음 | — | **수정함**: 쉬운 안내 문구로 바꾸고 상세 오류는 서버 로그로 |
| 화면 디자인 | 첫 구현은 노란 버튼 2개, 형광펜 남용, 회색 시각, 팀 표시 없음 등 디자인 시스템과 어긋남 | 디자인 시스템을 확인하기 전에 만듦 | **수정함**: 시안 3개 중 B(날짜 흐름 시트)로 다시 구현 |
| mock 답변 | 답변이 타임라인과 같은 목록을 한 번 더 나열 | — | **수정함**: 핵심 발언 한 줄 + 최근 언급만 |
| 답변 형광펜 | 시안 B는 답변의 핵심 구절 하나에 형광펜(`.hl`)을 칠했지만 구현에는 없음 | mock 답변은 핵심 구절을 고를 근거가 없음 | Claude 모드에서 핵심 구절을 받아 표시하는 방식 검토 |

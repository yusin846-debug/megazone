# AI 챗봇 실행 방식과 AIR Studio 연계

v0.2 | 2026-10-22 | 검토용 초안 · 챗봇 추가안 (기준: 05_AIR_Integration v0.1)

본 문서는 방송작가 인터뷰를 가상 제작사 에그이즈고잉에 적용한 설계 초안이다. 실제 에그이즈커밍의 조직 운영이나 AIR Studio의 확정 API를 설명하지 않는다. 아래 경로·도구 이름은 자체 계약 예시다.

## 현재 실행 방식

| 영역 | 제품 책임 (현재 구현) | AIR Studio 연계 후보 |
|---|---|---|
| 업무 | 챗봇은 조회 전용. 업무 상태를 바꾸지 않음 | 없음 |
| 실행 | `POST /api/chatbot` 한 번에 검색·답변까지 동기 처리 | Agent 워크플로 (질문 → 검색 도구 → 답변) |
| 데이터 | 질문마다 프로그램 회의 원문을 읽어 규칙 기반 검색 | **Data 지식베이스·검색** — 회의 수가 많아질 때 1순위 후보 |
| 운영 | 실패 시 규칙 기반 답변으로 대체 | Ops 관측 (응답 시간·실패율) |
| 통제 | 프로그램 권한을 백엔드에서 매번 검증 | Governance 사용량·감사 (FR-14와 연결) |

UI는 AI 공급자를 직접 부르지 않고 제품 서버(`/api/chatbot`)를 거친다 (기준 문서 원칙 준수).

### API 계약 (`web/src/app/api/chatbot/route.ts`)

| 요청 | 조건 | 응답 |
|---|---|---|
| `GET /api/chatbot` | 로그인 + 참여 프로그램 있음 | 200 `{ program, readable }` — 채팅 창이 현재 프로그램과 검색 가능 여부를 받음 |
| `POST /api/chatbot` `{ question }` | 정상 | 200 `{ program, answer, hits, keywords, provider, note? }` + 조회 기록 `chatbot.search` |
| 공통 | 로그인 안 함 | 401 "로그인이 필요해요." |
| 공통 | 참여 중인 프로그램 없음 | 404 "참여 중인 프로그램이 없어요." |
| POST | 운영자 역할만 있음 | 403 + 조회 기록 `chatbot.search_denied` |
| POST | 빈 질문 / 300자 초과 | 400 "질문을 입력해 주세요." / "질문은 300자 이내로 써 주세요." |

검색 대상 프로그램은 요청 본문으로 받지 않고 서버가 현재 선택된 프로그램(`activeProgram`)으로 정한다. MCP 도구로 바꿀 때도 같은 오류 기준을 유지한다.

### 공급자 전환

| `AGENT_PROVIDER` | 검색어 확장 | 답변 작성 |
|---|---|---|
| `mock` (기본) | 규칙 기반 단어 추출 + 제작 용어 사전 | 가장 관련 깊은 발언 한 줄 + 가장 최근 언급을 알려 주는 규칙 (발언 목록은 화면 타임라인이 보여 줌) |
| `anthropic` | Claude가 핵심 단어·비슷한 말·받아쓰기 오류 후보 제안 | Claude가 관련 회의 원문 전체(최근 회의부터 600줄까지)를 읽고 근거 발언 id를 인용해 답변. 프롬프트는 [프롬프트.md](프롬프트.md) |

### ExecutionAdapter를 거치지 않는 이유 [기준 문서와 차이]

기준 문서의 실행 어댑터(`start_run` 등)는 **회의 하나에 대한 장시간 업무 실행**(Run·StepRun·HumanTask)을 위한 계약이다. 챗봇은 여러 회의를 가로지르는 수 초짜리 조회이고 사람 확인·재개·부분 재실행이 없으므로 Run을 만들지 않는다. 대신 검색(`searchCorpus`)과 답변(`answerQuestion`)을 함수로 분리해, AIR 연계 시 이 경계만 교체할 수 있게 했다.

## MCP 도구 후보

| 도구 | 상태 | 입력 | 결과·보장 |
|---|---|---|---|
| get_transcript_segments | 기준 문서 후보 재사용 | meeting_id | 회의 하나의 발언 목록 |
| search_program_transcripts | 신규 후보 | program_id, query, variants | 프로그램 안 발언 검색 결과 (점수·일치 종류) |

도구 서버는 호출할 때마다 사용자·프로그램 권한을 검증한다. 다른 프로그램 id가 들어오면 거부한다. 챗봇 도구에는 쓰기 기능을 노출하지 않는다.

## 단계적 적용

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 제품 내부 규칙 검색 + mock 답변으로 화면·권한·범위 검증 | 완료 (2026-10-22, 로컬) |
| 2 | `anthropic` 공급자로 검색어 확장·답변 품질 확인 | 보류 — 추후 사람이 검토한 뒤 적용. API 키 발급 대기, 키를 받으면 [프롬프트.md](프롬프트.md) v0.2·v0.3 비교 시험부터 |
| 3 | 조회 기록 (FR-14a) / 사용량 기록 (FR-14b) | 조회 기록 완료 · 사용량 기록 보류 |
| 4 | 회의 수 증가 시 AIR Data 검색 또는 Vector DB로 검색 교체 | 후보 |

## 연동 검증 체크리스트

| 항목 | 확인할 내용 | 통과 증거 |
|---|---|---|
| 범위 | 다른 프로그램 원문이 검색 도구에 들어가지 않음 | AT-06~08 통과 기록 |
| 권한 | 운영자·비로그인 거부 | AT-09~10 통과 기록 |
| 장애 | AI 실패 시에도 검색 결과 반환 | 키 없이 anthropic 모드 실행 시 대체 응답 |
| 비용 | 질문당 토큰·응답 시간 | FR-14b 기록 |
